# Mini App «Калькулятор юнит-экономики»

Telegram Mini App для селлеров Wildberries и Ozon: за 1–2 минуты считает прибыль
с единицы товара, маржинальность, ROI и цену под нужную прибыль.

> Демо-проект для портфолио. Тарифы маркетплейсов, комиссии и налоги в код
> не зашиты — их вводит пользователь, потому что они меняются и зависят от
> категории товара.

## Возможности

- **Расчёт** — цена, себестоимость, комиссия, логистика, хранение, упаковка,
  реклама, процент выкупа, обратная логистика, система налогообложения
  (УСН 6%, УСН 15%, НПД 4%, своя ставка). Итог обновляется сразу при вводе.
- **Результат** — прибыль с единицы, маржинальность, ROI, диаграмма «куда
  уходит цена». Цвет итога: зелёный — прибыль, жёлтый — маржа ниже 10%,
  красный — убыток.
- **Обратный расчёт** — цена под целевую маржу (%) или прибыль (₽), прибыль
  с партии и точка безубыточности.
- **Мои товары** — до 20 сохранённых расчётов: открыть, дублировать, удалить.
  Хранятся в Telegram CloudStorage (доступны с любого устройства), вне
  Telegram — в localStorage.
- **Интеграция с Telegram** — тема из `themeParams` (светлая и тёмная без
  переключателей), `ready()` + `expand()`, MainButton «Рассчитать» /
  «Сохранить», BackButton, тактильный отклик.

## Стек

React 18, TypeScript, Vite, Vitest. Telegram WebApp SDK
(`telegram-web-app.js`). Без UI-библиотек и внешних шрифтов, без бэкенда.

## Запуск локально

Нужен Node.js 20+.

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тесты формул, формы и хранилища
npm run build      # проверка типов + сборка в dist/
npm run preview    # просмотр собранной версии
```

В обычном браузере приложение работает полностью: вместо MainButton и
BackButton Telegram показываются кнопки на странице, вместо CloudStorage
используется localStorage.

### Проверка внутри Telegram до деплоя

Telegram открывает Mini App только по HTTPS. Самый простой путь —
задеплоить на Vercel (ниже). Для быстрой проверки можно пробросить
локальный сервер через туннель, например:

```bash
npm run dev
npx cloudflared tunnel --url http://localhost:5173
```

и указать полученный `https://...trycloudflare.com` адрес в @BotFather.
Если Vite ругается на хост, добавьте его в `server.allowedHosts` в
`vite.config.ts`.

## Деплой на Vercel

1. Залейте репозиторий на GitHub.
2. На [vercel.com](https://vercel.com) → **Add New → Project** → выберите
   репозиторий. Настройки подхватятся из `vercel.json`
   (Framework: Vite, Build: `npm run build`, Output: `dist`).
3. Нажмите **Deploy**. Через минуту появится адрес вида
   `https://unit-economics-xxx.vercel.app`.

Каждый пуш в основную ветку будет автоматически пересобирать приложение.

Альтернатива — Netlify: конфиг в `netlify.toml`, шаги те же.

## Привязка к боту

1. В Telegram откройте [@BotFather](https://t.me/BotFather), создайте бота
   командой `/newbot` (или используйте существующего).
2. **Кнопка меню** (самый простой способ): `/mybots` → ваш бот →
   **Bot Settings → Menu Button → Configure menu button** → вставьте
   HTTPS-адрес с Vercel и название кнопки, например «Калькулятор».
3. **Прямая ссылка на Mini App** (для портфолио): `/newapp` → выберите бота →
   название, описание, картинка 640×360 → URL с Vercel → короткое имя,
   например `calc`. Ссылка будет вида `https://t.me/<имя_бота>/calc`.
4. Откройте бота на телефоне и нажмите кнопку меню.

## Формулы

Обозначения: P цена, C себестоимость, k комиссия %, L логистика,
S хранение, U упаковка, a реклама %, b процент выкупа (0..1),
R обратная логистика, t налог %.

| Величина | Формула |
| --- | --- |
| Комиссия | P × k / 100 |
| Реклама | P × a / 100 |
| Потери на невыкупах на выкупленную единицу | R × (1 − b) / b, при b > 0 |
| Расходы до налога | C + комиссия + L + S + U + реклама + потери |
| Налог УСН 6%, НПД, своя ставка | P × t / 100 |
| Налог УСН 15% | max(0, (P − расходы до налога) × t / 100) |
| Прибыль | P − расходы до налога − налог |
| Маржинальность, % | прибыль / P × 100 |
| ROI, % | прибыль / C × 100, при C > 0 |

**Цена под целевую маржу m** (налог от цены):
`P = (C + L + S + U + потери) / (1 − k/100 − a/100 − t/100 − m/100)`.
Если знаменатель ≤ 0 — «при таких процентах целевая маржа недостижима».

Для УСН 15% налог берётся с разницы, а не с цены, поэтому используется
точное решение (в долях): `P = F × (1 − t) / ((1 − k − a) × (1 − t) − m)`,
где F = C + L + S + U + потери. Так рекомендованная цена, подставленная
обратно в расчёт, даёт ровно целевую маржу.

**Цена под целевую прибыль X ₽**: `P = (F + X) / (1 − k − a − t)`,
для УСН 15%: `P = (F + X / (1 − t)) / (1 − k − a)`.

**Партия из q штук**: вложения = C × q, прибыль с партии = прибыль × q,
точка безубыточности = ⌈C × q / (прибыль + C)⌉ — каждая проданная штука
возвращает свою себестоимость плюс прибыль.

### Пример для сверки с Excel

| Поле | Пример 1 | Пример 2 |
| --- | --- | --- |
| Цена | 1000 | 1000 |
| Себестоимость | 400 | 400 |
| Комиссия | 15% | 15% |
| Логистика / хранение / упаковка | 50 / 10 / 20 | 50 / 10 / 20 |
| Реклама | 5% | 5% |
| Выкуп / обратная логистика | 100% / 0 | 50% / 100 |
| Налог | УСН 6% | УСН 15% |
| **Прибыль** | **260 ₽** | **187 ₽** |
| **Маржинальность** | **26%** | **18,7%** |
| **ROI** | **65%** | **46,75%** |

Пример 1: комиссия 150, реклама 50, расходы до налога
400 + 150 + 50 + 10 + 20 + 50 = 680, налог 1000 × 6% = 60,
прибыль 1000 − 680 − 60 = 260.

Пример 2: потери на невыкупах 100 × 0,5 / 0,5 = 100, расходы до налога
680 + 100 = 780, налог (1000 − 780) × 15% = 33, прибыль 1000 − 780 − 33 = 187.

Оба примера закреплены в тестах `src/calc.test.ts`.


## Критерии приёмки

- [ ] Открывается по ссылке из бота на телефоне (iOS/Android) и в десктопном Telegram
- [ ] Тёмная и светлая темы выглядят корректно
- [ ] Формулы совпадают с тестами и ручным расчётом в Excel (два примера выше)
- [ ] При любом вводе нет NaN и Infinity
- [ ] Расчёты сохраняются и остаются после перезапуска
- [ ] В консоли нет ошибок, `npm run build` проходит без предупреждений
